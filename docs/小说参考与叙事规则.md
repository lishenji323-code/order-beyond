# 小说参考与叙事规则

这次对用户提供的 17 部小说进行了文字提取、分段抽样和部分人物关键词检索。以下是用于设计的阅读观察，不是逐部通读后的完整人物评价。原文只作为研究资料，未打包到 demo、上传到 Figma，也不作为每次调用模型时的上下文。

## 从观察到 30 个特质

特质库是面向游戏的原创抽象，并非把某一小说男主原样移植。部分特质由这些观察直接启发；另外的特质用于补齐相处、亲密、内心、行事、底色五个维度，不为每一个词条强行指定小说出处。

避免把职业、长相和特质混成一类；“有钱”“高个子”“律师”不是性格。避免用同义标签凑数，例如不同时收录“爱吃醋”和“占有欲强”。“体贴细致”关注熟人的具体需求，“悲悯心软”关注更广泛的他人困境，区分作用对象。“缜密筹谋”关注信息与后手，“循规谨慎”关注规则与可预测性，区分决策方式。

## 生成规则

- 玩家输入姓名；世界、主线、人物原型仍由玩家选择，额外特质最多三个。
- 男主姓名从适配时代的姓名池抽选；女主背景从每个世界三种身份中抽选，并结合关系主线固定在存档中。
- 开局只用物件和职责露出女主的背景线索。没有背景介绍卡、自动生成提示或履历段落。
- 男主外貌在新故事创建时固定；第一幕不展示。后续根据动作和观察每次择取一个细节，不能反复报身高或全套外貌参数。
- 反差特质分配到不同情境，不把三个词条机械写进同一句。特质要改变人物的选择、表达方式与承担的代价。
- 保留玩家对关键回应和行为的决定权；选项不是保证结局的按钮。
