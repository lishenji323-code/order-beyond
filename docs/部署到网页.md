# 部署成朋友可以打开的网页

目标：一个链接发过去就能玩，可以加到手机主屏幕，前几场用你的额度，想长期玩就填自己的密钥。

推荐 Cloudflare Pages：静态站点、函数、KV 都在一处，免费额度足够朋友圈规模。

---

## 一、当前配置：全部走你的密钥

朋友不需要注册任何东西，点开链接、填一个邀请码就能玩。他们看到的设置页里密钥一栏是可不填的。

额度默认值（`src/engine/trial.ts`）按三五个人的规模定：

| 常量 | 默认 | 含义 |
|---|---|---|
| `TRIAL_TURNS` | 400 | 每人总共多少轮 |
| `TRIAL_BURST` | 40 | 每人每小时上限，防一个卡住的标签页跑整夜 |
| `DAILY_TURN_CAP` | 600 | 全站每天上限，链接外流时的兜底 |
| `MAX_TOKENS_CAP` | 8000 | 单次请求输出上限 |

这些是第二道防线。第一道是你在 OpenRouter 上给密钥设的额度，第二道是邀请码。

---

## 二、部署步骤

### 1. 建站

Cloudflare Dashboard → Workers & Pages → Create → Pages → 连接 Git 仓库。

构建设置：

| 项 | 值 |
|---|---|
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| Node 版本 | 22 或更高（环境变量 `NODE_VERSION=22`） |

`functions/api/story.ts` 会被 Pages 自动识别为 `/api/story`，不需要额外配置。

### 2. 建 KV

Workers & Pages → KV → Create namespace，名字随意。回到 Pages 项目 → Settings → Functions → KV namespace bindings，变量名必须是 **`TRIAL`**。

### 3. 设变量

Settings → Environment variables，Production：

| 变量 | 类型 | 值 |
|---|---|---|
| `OPENROUTER_KEY` | Secret | 你的 OpenRouter 密钥。**永远不会到浏览器** |
| `COOKIE_SECRET` | Secret | 随便一串长随机字符 |
| `TRIAL_MODELS` | 文本 | 允许的模型，逗号分隔，第一个是默认。例：`deepseek/deepseek-chat,deepseek/deepseek-v4.1-flash` |
| `TRIAL_CODE` | 文本 | 可选。邀请码。链接可能被转发出去就设一个 |
| `VITE_TRIAL` | 文本 | `1`。让前端在没有个人密钥时走 `/api/story` |
| `VITE_TRIAL_CODE` | 文本 | 与 `TRIAL_CODE` 相同；没设就留空 |

前两个必须是 Secret。`VITE_` 开头的会被编译进前端，**别把密钥放进这两个**。

### 4. 调额度

`src/engine/trial.ts` 顶部四个常量：

| 常量 | 默认 | 含义 |
|---|---|---|
| `TRIAL_TURNS` | 12 | 每人免费多少轮 |
| `TRIAL_BURST` | 20 | 每人每小时上限 |
| `DAILY_TURN_CAP` | 3000 | 全站每天上限，超过就对所有人关闭试玩 |
| `MAX_TOKENS_CAP` | 8000 | 单次请求的输出上限 |

真正保护账单的是后两个。每人 12 轮只是礼貌：清掉 cookie 就能再来一次。朋友圈范围这样够了，真要拦就靠 `TRIAL_CODE`。

按每轮约 9000 输入 + 2000 输出估算，`DAILY_TURN_CAP=3000` 相当于每天最多约 2700 万输入 token。**先按你能接受的日花费反推这个数**，OpenRouter 的价格在它的模型页上。

## 三、不开试玩的部署

任何静态托管都行（Cloudflare Pages / Vercel / Netlify）：构建命令 `npm run build`，输出目录 `dist`，不设 `VITE_TRIAL`。朋友第一次进去会被引导到设置页填自己的密钥。

---

## 四、加到主屏幕

已经配好，不用额外操作：

- `public/manifest.webmanifest`：名称、`standalone`、主题色，以及 192／512／maskable 三个图标
- `public/icons/`：图标由 `public/book-mark.svg` 渲染而成，深色底配亮色书页
- `index.html`：`apple-touch-icon` 与 iOS 的全屏 meta
- `scripts/build-offline.mjs`：图标一并进离线缓存

**iOS**：Safari → 分享 → 添加到主屏幕。必须用 Safari，Chrome on iOS 加出来的是快捷方式。
**Android**：Chrome 会自己弹安装提示，或菜单 → 安装应用。

两个前提：**必须是 HTTPS**（Pages 自带），**必须部署在域名根目录**。放子路径要改 `vite.config.ts` 的 `base`，以及 manifest 里的 `start_url`／`scope`／`id`。

图标想换：替换 `public/icons/` 下的 PNG 即可，尺寸和文件名保持一致。

## 五、几件需要知道的事

**故事存在访客自己的浏览器里**（IndexedDB），不经过你的服务器。所以每个人的存档天然是私有的，你也看不到。代价是换设备或清缓存就没了——要跨设备就需要账号和后端存储，那是另一个量级的工作。

**密钥存在访客的 localStorage**。朋友圈范围可以接受；如果链接会传得更远，建议改成 `sessionStorage`，关掉页面就失效。

**亲密尺度保持现状**（创建故事时三档可选）。这是按“只给朋友玩”的前提定的。若日后要公开，需要补：进入前的年龄确认、内容提示，并核对所选模型对成人内容的使用条款——很多模型的条款是禁止的，那会直接决定公开版能用哪些模型。

**试玩额度用完时**，界面显示的是函数返回的原话（“试玩的 12 轮已经用完……”），引导去填自己的密钥，故事不会丢，接着往下写就行。
